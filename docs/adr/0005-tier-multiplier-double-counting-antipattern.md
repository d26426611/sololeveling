# 反覆出現的 bug 模式：「級距已經算過一次，倍率又算了第二次」

平衡調校過程中透過模擬（數百輪自動化 playthrough）找到並修掉了**四個獨立位置、同一種錯誤模式**的 bug，記下來是為了讓下一次有人加新內容時能認出這個模式，不要再犯第五次：

1. **菁英/王倍率**：`monsters.js` 的怪物資料本身已經用 baseHp/baseAtk 編碼了「一般→菁英→王」的級距(例如平原野狼 50/12 → 菁英狼王 500/60 → 王 2000/100)，但 `combat.js` 又在這之上疊加 `isBoss ? 5 : 1` / `isElite ? 2 : 1` 這種額外倍率——級距被算了兩次，王在深度 20 就有 20000 血/300 攻，遠超玩家實際打得動的範圍。
2. **區域倍率**：同樣道理，`monsters.js` 各區域的怪物數值本身已經逐區域遞增(平原 30hp 一路到沙漠 3000hp，已經是 100x)，但 `biome.scaling`(1x→12x) 又乘了一次，複合成 1200x 落差。見 ADR 0004。
3. **裝備預設稀有度**：`itemPool.sets.sin`/`void` 套裝裡的 `路西法之傲` 這類物品，`baseAtk: 2000` 已經是寫死的「abyssal 級最終數值」，但物品生成邏輯不分青紅皂白地又套用了 `CONFIG.rarity.abyssal.mult(10.0x)`，做出 20000 攻擊力的裝備。
4. **`depthScale` 自我疊算**：修 1、2 點時新設計的 `depthScale = 1 + biomeDepth*0.05 + Player.depth*0.01`，對第一個區域(平原)而言 `biomeDepth` 恆等於 `Player.depth`，兩個分量疊加在同一個數字上，等於又把平原自己的深度算了兩次。見 ADR 0004。

**共通特徵**：資料裡已經有一個欄位/數值代表「這東西的最終強度/級距」，但程式邏輯裡又有一段獨立的倍率邏輯，用「這是菁英/這是王/這是高稀有度/這是後面的區域」之類的旗標去做**額外**加乘——兩段邏輯各自都合理，但沒人意識到彼此在算同一件事。

**日後加新內容時的檢查方式**：在對某個數值套用「因為這是 X 所以要更強」的倍率之前，先問一句——這個數值本身（base 模板、前一步驟算出來的稀有度/深度加成）是不是已經反映了「這是 X」這件事？如果是，額外的倍率通常應該拿掉，或者權重要遠低於直覺。
